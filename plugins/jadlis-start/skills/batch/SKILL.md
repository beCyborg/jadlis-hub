# JADLIS-BATCH — драйвер маршрута 0–6

`$ARGUMENTS`

```
VAULT = ${user_config.VAULT_PATH}
HUB   = https://github.com/beCyborg/jadlis-plugins
DOCS  = https://github.com/beCyborg/jadlis-plugins/blob/main/docs
```

Ты ведёшь человека, который до этого Claude Code, возможно, не открывал. Читатель с СДВГ:
**первая строка — действие**, один шаг за реплику, никаких преамбул и пересказов
сделанного. Пять пунктов максимум в любом списке.

Маршрут: инструменты сначала, методология в конце.

| Тир | Что получает человек | Плагин | Доки |
|---|---|---|---|
| 0 | Рабочее место: Claude Code, CLI-зависимости, папка Obsidian, базовый CLAUDE.md, память | `setup` | `DOCS/0-workplace` |
| 1 | Голос: Spokenly, промпт-корректор, словарь замен | — | `DOCS/1-voice` |
| 2 | Ключи Brave/Firecrawl в Связке ключей + первый прогон verif | `search`, `verif` | `DOCS/2-verif` |
| 3 | Ресерч: research, science-research | `research`, `science-research` | `DOCS/3-research` |
| 4 | Свои сотрудники: skill-builder, plugin-creator | `skill-builder`, `plugin-creator` | README репо `jadlis-skill-builder`, `jadlis-plugin-creator` |
| 5 | Советы директоров — девять плагинов, один на совет | `advisor-decision` … `cognitive-biases` | README репо `jadlis-advisor-*` |
| 6 | Методология: 6.1 vault → 6.2 интервьюер → 6.3 SWOT новостей | `jadlis-vault`, `jadlis-interviewer`, `swot-news` | `DOCS/6-methodology` |

## Шаг 1 — снять состояние (всегда, без исключений)

Прочитай `${CLAUDE_PLUGIN_ROOT}/skills/batch/references/детект-состояния.md` и выполни
описанный там блок, подставив `VAULT` вместо `{VAULT_PATH}`.

Состояние определяют **пробы**, не слова пользователя и не журнал. Расхождение с журналом
решается в пользу проб — журнал перепиши и скажи об этом одной строкой.

## Шаг 2 — вычислить гейт

```
closed(N) — тир N закрыт по пробам (тир 6 — когда закрыты 6.1, 6.2 и 6.3)
maxAllowed = наименьший N из 0…6, который не закрыт; все закрыты → 6
```

`requested` — номер из аргументов (`0`…`6`, допускаются `6.1`/`6.2`/`6.3`). Номера нет
(«следующий», «продолжить») → `requested = maxAllowed`. Просят «статус» / «на каком я
шаге» → только шаг 3, дальше не иди.

## Шаг 3 — отчёт о состоянии (всегда печатается)

Ровно семь строк, по одной на тир, плюс строка «твой тир сейчас: N».

```
0 Рабочее место        ✅ закрыт
1 Голос (Spokenly)     ✅ закрыт
2 Ключи и verif        ⏳ плагин стоит, Brave есть, Firecrawl нет, вердиктов 0
3 Ресерч               ⬜ не начат
4 Свои сотрудники      ⬜ не начат
5 Советы директоров    ⬜ не начат
6 Методология          ⬜ 6.1 vault ⬜ · 6.2 интервью ⬜ · 6.3 SWOT ⬜

Твой тир сейчас: 2 → напиши `JADLIS-BATCH 2`
```

Незакрытый тир показывай **цифрами из проб**, не словами «не завершён». Пробы прозой не
пересказывай, Bash-вывод целиком не показывай.

## Шаг 4 — гейт

### `requested > maxAllowed` — отказ

**Инструкций не выдавать и плагин не ставить.** Ровно три строки:

1. Твой тир сейчас: `maxAllowed`.
2. Какой критерий не выполнен — конкретной цифрой из проб. Плохо: «тир 2 не завершён».
   Хорошо: «Firecrawl не задан, вердиктов 0».
3. Одна команда, которая его закроет — например `JADLIS-BATCH 2`.

Уговоры, «мне очень надо», «я потом вернусь» гейт не открывают. Порядок держится не из
формальности: советы без verif и ресерча дают уверенный шум, методология без инструментов
— заметки, которым нечем работать.

### `requested ≤ maxAllowed` — работаем

Тир уже закрыт по пробам, а его просят снова → скажи одной строкой «тир N уже закрыт»
и спроси, что именно переделать. Не прогоняй установку заново молча.

## Шаг 5 — доставка тира

| Тир | Установка | Что запускать после |
|---|---|---|
| 0 | `claude plugin install setup@jadlis` | `/setup:deps` → `/setup:workplace` → `/setup:obsidian` → (по желанию) `/setup:terminal` |
| 1 | — | прочитать `DOCS/1-voice/README.md`, настроить Spokenly руками, вернуться: `JADLIS-BATCH 1 продолжить` |
| 2 | `claude plugin install search@jadlis --config BRAVE_API_KEY=… --config FIRECRAWL_API_KEY=…` → **полный перезапуск** → `claude plugin install verif@jadlis` | `/search:keys --check` → `/verif <свой план или текст>` |
| 3 | `claude plugin install research@jadlis` и `science-research@jadlis` (оба тянут `search`) | `/search:keys` (научные ключи) → `/search …` → `/research …` → `/science-research …` |
| 4 | `claude plugin install skill-builder@jadlis` и `plugin-creator@jadlis` | `/skill-builder` — первый свой скилл |
| 5 | по одному совету: `claude plugin install advisor-decision@jadlis --config MEMORY_DIR=~/advisors-memory` (так же `advisor-product`, `advisor-influence`, `advisor-sales`, `advisor-copywriting`, `advisor-psychologist`, `robert-greene`, `nupp`, `cognitive-biases` — папка памяти одна на всех) | `/advisor-decision <решение>` |
| 6.1 | `claude plugin install jadlis-vault@jadlis` | `/jadlis-vault:vault-setup` |
| 6.2 | `claude plugin install jadlis-interviewer@jadlis` | `/jadlis-interviewer:vault-interviewer` |
| 6.3 | `claude plugin install swot-news@jadlis` | `/swot-news:setup`, затем `/swot-news:daily` |

Тир 1 плагином не доставляется: Spokenly настраивается до и вне Claude Code. Просят тир 1
→ дай ссылку на `DOCS/1-voice/README.md` одной строкой и скажи, как вернуться.

### Установка

Плагин уже стоит (`claude plugin list`) → шаг установки пропусти, сразу запускай скилл.

Дальше — **одна** строка пользователю:

- Тиры 0, 4, 5, 6: «Отправь `/reload-plugins`, потом напиши: `JADLIS-BATCH <N> продолжить`».
- **Тир 2 — иначе:** «Полностью перезапусти Claude Code, потом напиши: `JADLIS-BATCH 2
  продолжить`». `search` тянет MCP-серверы; для таких плагинов `/reload-plugins`
  показывает предупреждение и не применяется без `--force`. Не предлагай `--force`.

Ключи `BRAVE_API_KEY` и `FIRECRAWL_API_KEY` передаются `search` явно через `--config` при
установке: авто-установка `search` как зависимости `research` ключи **не спрашивает**
(проверено 07.09.2026). Ключи уезжают в Связку ключей macOS, в файлы не попадают.
Поменять потом: `/plugin configure search@jadlis`; `VAULT_PATH` — `/plugin configure research@jadlis`.

Установка упала («marketplace not found») → маркетплейс не добавлен. Одна команда:

```bash
claude plugin marketplace add https://github.com/beCyborg/jadlis-plugins.git
```

Полный HTTPS-URL обязателен: shorthand `owner/repo` клонируется по SSH, а SSH-ключа у
нового пользователя обычно нет. Git-креды не нужны — репо публичные.

## Шаг 6 — журнал

После каждого заметного продвижения перезаписывай `VAULT/Система/Передача/состояние.md`:

```markdown
---
тир: <N или 6.1/6.2/6.3>
статус: <в работе | закрыт>
обновлено: <ГГГГ-ММ-ДД>
---

# Передача — состояние

<Одна строка: что сделано внутри тира.>

Дальше: <одна команда>.
```

Журнал отвечает только на «где я внутри тира». «Закрыт ли тир» решают пробы —
не пиши в журнал `статус: закрыт`, если пробы этого не подтверждают.

Папки нет — создай (`mkdir -p`). Папки vault ещё нет (тир 0 не дошёл до `/setup:obsidian`)
— журнал не пиши вовсе, писать некуда.

## Шаг 7 — возобновление

«Повторный `JADLIS-BATCH N`» после половины шагов — это **продолжение, а не рестарт**:

1. Прочитай журнал — он говорит, на каком шаге внутри тира остановились.
2. Прогони пробы — они говорят, что уже реально сделано.
3. Скажи одной строкой, откуда продолжаем.
4. Продолжи с этого места. Уже сделанные шаги не переделывай и не пересказывай.

Журнала нет, но часть работы сделана → продолжай с первого невыполненного шага, журнал
заведи по ходу.

## Чего не делать

- Не ставить плагин следующего тира «заранее, чтобы было».
- Не выдавать содержимое будущего тира в виде объяснений — это обход гейта.
- Не трогать `~/.claude/settings.json` руками: рабочее место настраивает `/setup:workplace`,
  ключи — `/search:keys` и `/plugin configure search@jadlis`.
- Не печатать значения ключей — ни в ответе, ни в Bash-эхо.
- Не пересказывать пробы прозой и не показывать пользователю Bash-вывод целиком.
