# Зависимости рабочего места

`$ARGUMENTS`

Читателю с СДВГ: **первая строка — действие**, один шаг за реплику, никаких преамбул.
Вывод команд целиком не показывать — только таблицу PASS/FAIL.

## Шаг 1 — одна проба, одна таблица

Выполни ровно этот блок. Он ничего не ставит и не меняет.

```bash
for c in brew claude jq node npx git gh; do
  if command -v "$c" >/dev/null 2>&1; then
    v=$("$c" --version 2>/dev/null | head -1 | cut -c1-40)
    printf '%-6s PASS  %s\n' "$c" "$v"
  else
    printf '%-6s FAIL\n' "$c"
  fi
done
printf 'macOS  %s (%s)\n' "$(sw_vers -productVersion 2>/dev/null)" "$(uname -m)"
```

Напечатай ответ таблицей: колонки «Что · Статус · Зачем». Строк ровно семь.

| Что | Зачем |
|---|---|
| `brew` | менеджер пакетов macOS: через него ставится всё остальное |
| `claude` | CLI Claude Code — им ставятся плагины (`claude plugin install …`) |
| `jq` | читает и правит JSON-настройки; без него скилл `workplace` не сольёт `settings.json` |
| `node` / `npx` | на них живут MCP-серверы плагинов следующих тиров |
| `git` | версии, клоны репозиториев, работа плагинов с кодом |
| `gh` | опционально: GitHub из терминала |

Всё PASS — скажи одной строкой «зависимости на месте, дальше `/setup:workplace`» и
остановись. Ничего не переустанавливай.

## Шаг 2 — почему `claude` может быть FAIL, даже если ты в приложении

Десктопное приложение Claude Code **не ставит** CLI `claude` — внутри у него свой
встроенный движок, но команды `claude …` в Bash берутся из отдельной установки.
Скажи это одной строкой, если `claude` в FAIL: без CLI не встанут плагины следующих тиров.

## Шаг 3 — спросить, что ставим

Собери список FAIL и задай **один** `AskUserQuestion` (по вопросу на пакет, максимум
четыре за раз; больше — вторым вызовом). Формулировка вопроса — «Ставим `<пакет>`?»,
варианты «Ставлю» / «Пропустить», в описании варианта — одна строка «зачем» из таблицы.

`gh` предлагай последним и помечай как необязательный.

## Шаг 4 — установка, по одному пакету

Ставь **только** то, на что сказали «Ставлю». После каждой установки — одна строка
результата, не вывод команды.

### Homebrew (ставится первым, от него зависят остальные)

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Скажи заранее три вещи, по строке:

1. Команда спросит пароль от Mac — это `sudo`, так устроен официальный установщик.
2. На Apple Silicon Homebrew ложится в `/opt/homebrew`, на Intel — в `/usr/local`.
3. После установки её нужно прописать в шелл, иначе `brew` не найдётся в новой сессии:

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

Установка Homebrew долгая и интерактивная. Если Bash в текущем окружении её не тянет —
отдай команду пользователю строкой «набери это в Терминале и вернись» и жди.

### Остальные пакеты

```bash
brew install jq            # обработка JSON
brew install node          # Node.js + npx
brew install git           # git новее системного
brew install gh            # опционально: GitHub CLI
```

`git` обычно уже есть в Command Line Tools от Apple — если проба дала PASS, `brew install git`
не нужен. Нет ни того ни другого и Homebrew ставить не хотят — альтернатива одной строкой:
`xcode-select --install`.

### CLI `claude`

Два пути, оба официальные. Спроси, какой:

```bash
curl -fsSL https://claude.ai/install.sh | bash    # нативный: сам обновляется в фоне
brew install --cask claude-code                    # через Homebrew: обновлять руками
```

Нативный — дефолт: обновления приезжают сами. Homebrew — если хочется держать всё
в одном менеджере; тогда обновление руками через `brew upgrade claude-code`.

После установки перезапусти шелл или скажи пользователю открыть новое окно терминала —
`claude` появляется в `PATH` только там.

## Шаг 5 — повторная проба и итог

2. Дальше: `/setup:workplace`.

починить. Не предлагай три обходных пути сразу.

## Чего не делать

- Не ставить ничего без явного «Ставлю» в ответе на вопрос.
- Не ставить `sudo npm install -g` — ломает права и не нужно ни одному из пакетов.
- Не трогать `~/.claude/settings.json` — это работа `/setup:workplace`.
- Не показывать вывод `brew install` целиком: строка результата, а не простыня.
- Не ставить пакеты «про запас», которых нет в таблице.
